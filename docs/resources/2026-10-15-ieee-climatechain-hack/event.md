## 4. Submission format / requirements

Devpost overview, "What to Submit" (verbatim):
```
- Track Alignment: Clearly state the track you've chosen and how your project addresses the challenge.
- Project Description: Explain the problem, your solution, target users, how it can scale and how easily it can be adopted.
- Demo Video (3–5 mins): Showcase your project in action, highlighting key features and functionality.
- Code Repository: Provide a public GitHub (or equivalent) link with source code and documentation.
- Prototype / Demo: Share a working prototype, mockup, or proof-of-concept.
- Submission Deadline: Ensure your project is submitted before the official deadline to be eligible for judging.
```
Devpost rules "Project and Submission Requirements" (verbatim): Track Alignment; `Demo Video (3–5 mins)`; `Code Repository: Include a link to your GitHub repo (or equivalent) that contains the source code and any relevant documentation.`; Deadline. (No "public" word, no Project Description, no Prototype line on the rules page.)

IEEE Blockchain Türkiye page (verbatim; **not on Devpost**):
```
Technical Deliverables
- Working prototype or proof-of-concept (deployed on test net acceptable)
- Source code repository (GitHub/GitLab) with clear documentation
- Architecture diagram and technical specification
- 3-minute video demonstration
- Security and data integrity assessment document
Impact/Business Deliverables
- Problem statement and solution overview (max 2 pages)
- Climate impact assessment and carbon reduction projections
- Implementation and adoption strategy
- Scalability and sustainability roadmap
- User testing results (if applicable)
```

## 5. Judging criteria — VERBATIM

**Devpost overview "Judging Criteria"** (https://ieee-climatechain-hack.devpost.com/):
```
- Climate Impact How effectively the solution addresses a real climate or environmental challenge. Does the solution contribute to improving sustainability, environmental transparency, carbon tracking, renewable energy adoption, or ecosystem protection?
- Innovation & Creativity Is the idea fresh, innovative, and exciting? Does it take a unique approach to applying blockchain or emerging technologies to solve climate-related challenges within the chosen track?
- Technical Execution Does the project function as intend? Does it demonstrate effective use of tools such as blockchain, smart contracts, AI, data platforms, or environmental data integration?
- Practical Usefulness How practical and scalable is the solution? Could the project realistically be used by organizations, communities, policymakers, or businesses to improve climate action, sustainability, or environmental monitoring?
- Presentation & Communication Is the demo clear, engaging, and easy to understand? Does the presentation effectively communicate? 1) the climate problem being addressed 2) how the solution works 3) the potential real-world environmental impact
```
**Devpost rules "Judging Criteria and Winner Selection"** (https://ieee-climatechain-hack.devpost.com/rules) — same five, names/wording differ slightly:
```
🌍 Climate Impact — How effectively does the project address a real climate or environmental challenge? Does the solution contribute to improving sustainability, environmental transparency, carbon tracking, renewable energy adoption, or ecosystem protection?
✨ Innovation & Creativity — Is the idea fresh, innovative, and exciting? Does it take a unique approach to applying blockchain or emerging technologies to solve climate-related challenges within the chosen track?
🛠️ Technical Execution — Does the project function as intended? Is the technology behind it well-implemented, technically sound, and appropriate for the proposed solution? Does it demonstrate effective use of tools such as blockchain, smart contracts, AI, data platforms, or environmental data integration?
📈 Practical Usefulness — How practical and scalable is the solution? Could the project realistically be used by organizations, communities, policymakers, or businesses to improve climate action, sustainability, or environmental monitoring?
🎥 Presentation & Storytelling — Is the demo clear, engaging, and easy to understand? Does the presentation effectively communicate: the climate problem being addressed / how the solution works / the potential real-world environmental impact
```
**Weights on Devpost: not published.** ⚠ **But** the organizer's own page (https://cmte.ieee.org/turkiye-blockchain/hackatlon/) publishes a *different* criteria set with weights — recorded verbatim, not reconciled:

```
Submission Categories
- 70% Technical Innovation & Blockchain Implementation
- 20% Climate Impact & Environmental Benefit
- 10% Scalability & Real-World Implementation Potential

Evaluation Criteria (Weighted)
- Climate Impact & Environmental Benefit (30%)
- Technical Innovation & Blockchain Implementation (30%)
- Feasibility & Implementation Quality (10%)
- Data Security & Transparency (10%)
- User Experience & Design (10%)
- Scalability & Sustainability (10%)
```
(The two IEEE-page lists are themselves inconsistent: 70/20/10 vs 30/30/10/10/10/10.)
